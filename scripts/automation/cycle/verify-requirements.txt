# Verification requirement set for the cloud cycle's Day 4 sessions.
#
# WHY THIS EXISTS, AND WHY IT IS NOT `.[dev]`
# ------------------------------------------
# Day 4 sessions must run `pytest tests/unit` inside a ~15-minute wall clock, with no usable
# internet except PyPI. Installing the project's `dev` extra from PyPI DOES NOT FINISH: measured
# twice on 2026-09-16, the install was still running at ~10 minutes and `import duckdb` still
# failed, so the verify phase reported `unit=not-run-no-interpreter` and certified nothing.
#
# The `dev` extra is a SUPERSET of what running the tests needs. It also carries the lint, type,
# mutation, SBOM and audit toolchain - ruff, mypy, pandas-stubs, mutmut, build, pip-audit,
# cyclonedx-bom - plus the causal/bench stack (scipy, causal-learn, hyppo, networkx, pyarrow) and
# huggingface_hub. None of that is imported by `tests/unit`.
#
# This list is instead derived from evidence: the third-party modules actually imported across the
# 234 files in `tests/unit` (click, cryptography, duckdb, httpx, jsonschema, pandas, pydantic,
# pytest, rich, sqlglot, typer, yaml, z3) plus the package's own declared runtime dependencies,
# which are imported transitively the moment a test imports `dataforge`.
#
# Wheels for this set are staged at `/workspace/wheels/` so a fire can install with `--no-index`.
# Regenerate with `scripts/automation/cycle/build_wheelhouse.ps1`.
#
# TWO CONSTRAINTS THAT WILL BITE IF CHANGED
# -----------------------------------------
# 1. `pytest-xdist` IS MANDATORY, even though no test imports it and even when running serially.
#    `pyproject.toml` sets `addopts = "-ra --strict-markers --strict-config --dist loadgroup"`, and
#    `--dist loadgroup` is an xdist option. Without xdist installed, EVERY pytest invocation dies at
#    startup on an unrecognised argument - it does not degrade, it fails.
# 2. `psutil` is required for `-n logical`, which FALLS BACK SILENTLY to physical cores without it.
#
# Version floors mirror `pyproject.toml`. `numpy` keeps its `<2.5` cap and `typer` its `<0.25` cap
# for the reasons documented there; dropping either here would resolve a different tree than CI.

# --- imported TRANSITIVELY by dataforge/ modules that tests import ---
# These are invisible if you only grep the import lines of `tests/unit/*.py`, which is how they were
# missed on the first build. A probe fire then measured the cost exactly: 37 collection errors, i.e.
# `tenacity` in 34 files, `networkx` in 2, `fastapi` in 1. A collection error is worse than a test
# failure, because the test never ran at all while the run still produces a tidy summary line.
# Derive this section from what the SUITE reports missing, not from reading test imports.
tenacity>=8.3

# scipy is imported by the causal modules; python-multipart is pulled in by FastAPI form handling.
# Both were found the same way as the three above - by the suite, not by reading imports.
scipy>=1.13

# --- required by Day 4's certification checks, not by the tests ---
# `ruff format --check` passing on the touched paths is a CERTIFICATION PRECONDITION, and a failure
# is a hard stop that makes the local gate discard the patch. Without ruff staged here, Day 4 cannot
# establish a condition it is required to establish. Range mirrors pyproject: 0.16 began formatting
# Python inside Markdown, so an unbounded range makes the gate depend on which day it ran.
ruff>=0.16.2,<0.17
